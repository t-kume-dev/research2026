## 0. 研究のストーリー

### 一本の筋

1. **自分の良い状態を再現できない。** 上達したいが、何を直せばいいか分からない。
   画面が返すのは命中率という結果だけで、身体をどう変えればいいかは教えてくれない
2. **だから量でしか解決できず、崩れても立て直せない**（実害1・実害2）
3. **必要なのは「今日のあなたはここがずれている」と言ってくれるもの**、すなわちフィードバックである
4. **だがフィードバックを作るには、返す中身が要る。** 何を返せば練習に使えるのかが分かっていない
5. **1本目で「返すべき指標」を同定し**、個人の良い状態と悪い状態を分ける身体的な量が
   実際に存在するのかを確かめる
6. **2本目でそれを返し、直せるかを確かめる**

一行にすると次のようになる。

> 練習に使えるフィードバックを作りたい。そのためにまず何を返せばいいかを見つけ、次にそれが効くか確かめる。

**2本立ては研究遂行上の都合ではなく、このストーリーの必然である。** 指標がなければフィードバックは
作れないため、順番が決まっている。1本目は単独の計測研究ではなく、フィードバックシステムの中身を作る工程
と位置づける。

### 各決定がストーリーのどこにいるか

| 決定 | ストーリー上の役割 |
| --- | --- |
| 自己基準 | 返す内容が「あなたの良い日はこうだった」になる。他人の型を返しても実行できない。そもそもエイムは個人差が激しく、正解のロールモデルを作ること自体が困難 |
| 日をまたぐ | 良い日と悪い日の対比が、返す素材そのもの |
| 力みを主要指標に | 最初に返す候補。文献的に最も有望 |
| 計測項目を絞る | 毎日着けて練習する前提。重い装備は練習方法にならない |
| 成果を2本に分ける | 上記4→5→6の順序をそのまま2本に割ったもの |

### 何を支援すると言うのか — 「上達」ではなく「実力を出し切れるようにする」

自己基準を採ると、支援の対象は「到達点を上げること」ではなく「**自分の良い状態を再現すること**」になる。
上達ではなく安定に見えるが、両者は別物ではない。

- **再現性の向上は上達の一部である。** 文献表の PLOS ONE 2020 は、巧緻運動の学習に伴って EMG の
  変動性が減少することを示している。上達の正体の一部が、そもそも「ばらつきが減ること」である
- **ベストを出せる頻度が上がることも上達である。** たまに出る最高値より、毎回出せる実力の方が強い
- **自己基準は天井にならない。** 基準を固定テンプレートにせず、直近N日の良い試行から毎回作り直せば、
  良い試行の更新とともに基準も上がる。さらに基準を「良い試行の平均」ではなく
  「**自分の上位試行**」に取れば、自分の分布の中で上向きの圧がかかる

ただし、主張できる範囲は正直に分ける必要がある。

| 主張 | 強さ |
| --- | --- |
| 実力を出し切れるようになる（再現性の向上） | **示す**。主要な結果 |
| 練習効率が上がる（同じ到達点に少ない練習量で届く） | **示せる可能性がある**。計画書10章の「練習時間あたりの上達率」 |
| 到達点そのものが上がる | **議論で述べるに留める**。長期の訓練が必要で、修士の期間では測れない |

したがって研究の掲げ方は「上達を支援する」ではなく **「実力を出し切れるようにする」** とする。
この方が正確であり、実害2（調子に振り回される）そのものを指しており、プレイヤーの実感にも近い。

**この理由で他者基準に戻してはならない。** 天井を上げたいという動機で熟達者基準を復活させると、
個人差という本質的リスクが戻ってくる（Park 2021 は13個の通説のうち6個しか支持していない）。
天井は「自分の上位試行を基準にする」ことで上げる。

### 弱点

「どこを直すか」は示せるが、「**どう**直すか」は計測から直接は出ない。「今日は同時収縮が高い」までは
言えても、「だから力を抜けば良くなる」は別の主張である。差があることと、直せば改善することは違う。

ただし自己基準にはこの穴を塞ぐ性質がある。「どう」の答えは自分の良かった試行の中に既に入っており、
「この前うまくいったときはこうだった」と言えるだけで実行可能な指示になる。他人の真似ではなく
自分の再現なので、個人差の問題も発生しない。これは自己基準を選ぶ理由として最も強い。

## 2. 主要指標の仮置き

### なぜ力みを主要指標に置けるのか

事前登録が求めるのは「データを見る前に、理論的な根拠に基づいて決める」ことである。力みには根拠がある。

- 学習初期は拮抗筋の同時収縮で関節を固め、内部モデルの獲得とともに減る（Sci Rep 2018）
- 手首中心の微細動作でも熟達と同時収縮が対応する（drummers, 2021）
- 巧緻運動の学習でEMGの変動性が減る（PLOS ONE 2020）

**データから見つけたのではなく文献から立てた仮説**なので、事前登録として正当である。後付けではない。

これにより多重比較の問題が消え、センサ配置・特徴量・可視化がすべて確定するため実装をすぐ始められる。

### 外れた場合

主要指標で差が出なければ「**調子は力みには現れなかった**」という情報量のあるネガティブ結果になる。
そのうえで探索的に他の系統（変動性・タイミングなど）を見て「実は変動性だったようだ」と報告できる。
「示した」とは言えないが、「見つかった、2本目で検証する」という形にすれば2本立ての構成に乗る。
1本目で力みを潰しておく方が、2本目の設計は正確になる。

### 力みの定義（仮置き・要確認）

「力み」という言葉のままだと後から都合よく定義できてしまい、事前登録の意味が消える。
計算式のレベルまで確定させる必要があるため、以下を仮置きする。

#### 前提1: 問題は「動かしている最中の過剰」である

静止区間（ターゲット待機中など）の残余活動を力みとする案を検討したが、**待機中は調子に関係なく
誰でも力まないため、日による差が出ない**と判断して取り下げた。

捉えたいのは、**エイムを振っている最中に必要以上に力んでいること**である。

#### 前提2: 単一筋の分離ができない

Trigno の標準センサは、前腕の個々の筋に対して大きすぎる。ECR や FCR を単独で拾うことができず、
隣接筋のクロストークが避けられない。このため、**筋ペアの共収縮指数（CCI）はそのままでは成立しない**。

#### 課題: 必要な力と過剰な力をどう分けるか

動作中の高い筋活動は、過剰とは限らない。大きく速く振れば、それに見合った活動が出るのは当然である。
**「その動きに必要な量」を見積もり、それを超えた分を取り出す必要がある。**

#### 主要指標（仮置き）: 出力に対する残差

```
力み = 実際のEMG − その動きから予測されるEMG
```

| 項目 | 仮置きの値 | 理由 |
| --- | --- | --- |
| **定義** | マウス側の運動学（移動距離、ピーク速度、加速度、動作時間）から EMG を予測するモデルを立て、その**残差**を力みとする | 動きの大きさで説明できる分が引かれるため、必要な力と過剰な力が原理的に分離される |
| **モデルの学習データ** | **自分の良い試行のみ**で学習する | 自己基準が定義に内蔵される。残差が正に大きい＝いつもより多い筋活動で同じ動きをしている |
| **区間** | 動作区間（ターゲット出現から命中まで） | 捉えたいのは動作中の過剰であるため |
| **チャンネル** | 伸筋側1ch（背側）。屈筋側も記録する | **どの筋かを特定する必要がないため、クロストークの影響を受けない**。これがこの定義の最大の利点 |
| **正規化** | **その日に測定したMVC** | 日をまたぐと電極位置が変わるため、日ごとに取り直さないと日間比較が成立しない。**仮置きではなく必須** |
| **安静参照** | 毎回の記録の頭に、マウスに手を置いたまま10秒静止して記録する | **指標ではなく正規化の補助。** 座り方や肘の位置が日によって変わると保持活動の床が上下し、姿勢の違いを力みと誤認するため、MVCと合わせて2点で補正する |
| **方向** | 両側 | 力みすぎも脱力しすぎも悪い可能性があるため、向きを決め打ちしない |
| **データの持ち方** | **連続量で保持し、閾値は提示の段階でかける** | 最初から二値化すると情報が落ち、かつ閾値という自由パラメータが増えて後から都合よく決められてしまう |

必要なのはマウスの運動学ログだが、これはタスク側が出力するため追加の計測コストはない。

#### 対抗案

| 案 | 中身 | 評価 |
| --- | --- | --- |
| **効率比** | EMG積分 ÷ 移動距離 | 残差方式の簡易版。粗いが頑健で説明しやすい。サニティチェックに使える |
| **加速相の拮抗筋活動** | 振り出している最中の逆方向の筋活動は、定義上ほぼ不要 | 筋は通っているが、伸筋群と屈筋群の分離が前提。区画レベルで取れるかどうかに依存する |
| **弛緩の速さ** | クリック後に活動がベースラインへ戻る速度 | 「力が抜けない」ことを捉える。動作中ではないが、力みの別の側面 |

#### 要確認事項（2026年10〜11月）

上記はいずれも未検証である。機材スパイクと自己記録の中で次を確認する。

| # | 確認すること | 確認方法 | 結果による分岐 |
| --- | --- | --- | --- |
| A | **残差モデルを作れるだけの試行数が取れるか** | 1回20分の記録で何試行取れるかを実測する | 足りなければ記録時間を延ばすか、効率比（対抗案）に落とす |
| B | **マウス運動学から EMG がそもそも予測できるか** | 自己記録の初期データで、距離・速度から EMG を回帰し、説明力を見る | 予測がまったく効かないなら残差方式は成立しない。効率比に切り替える |
| C | **区画レベルの分離が取れるか** | 抵抗をかけた手関節伸展と屈曲をそれぞれ行い、背側センサと掌側センサが自分の動作に強く、相手の動作に弱く反応するかを見る | 比が3:1程度取れれば「加速相の拮抗筋活動」を対抗案として使える |
| D | **Trigno Mini / Quattro が使えるか** | 研究室の在庫、貸出、価格を確認。4mm電極で小さく隣接した筋向けに用意されている。同じベースステーションに繋がる | 使えれば単一筋の分離が可能になり、Cの精度が上がる |

#### 優先順位

1. **出力に対する残差**を力みの定義にする — 必要な力と過剰な力を分離でき、1チャンネルで済むため本命
2. **効率比**を併記する — 残差方式が不調な場合の受け皿
3. **加速相の拮抗筋活動**（確認C）が使えれば対抗案として検討する
4. いずれも不調なら**マウス圧を主要指標に格上げする** — クロストークが原理的に存在しない


### 個人差をどこに残すか

力みを主要指標にしても個人差の論点は捨てずに済む。

- **力みの量** → 主要指標。全員共通の仮説として検証する
- **どこで力むか**（腕＝EMG か 指＝マウス圧 か）→ 人によって違ってよい

腕と指の2択なので探索の幅が狭く、多重比較を起こさずに「調子の崩れ方は人によって違う」を主張できる。

### 探索的に見る特徴（主要指標ではない）

同じ EMG とマウス圧から取れるが、**すべて探索的**として報告する。「示した」とは書かない。

| 系統 | 中身 |
| --- | --- |
| 変動性 | 試行間の分散、波形の再現性 |
| タイミング | 筋活動の立ち上がり時刻、圧力ピークと命中の時間差 |
| 配分 | 伸筋/屈筋比、EMGと圧力の比 |
| 収束 | セッション内で落ち着くまでの試行数（ウォームアップの速さ） |

### 各項目の補足

**Q2（ラベル）**: 身体側で定義すると循環するため外から与える必要がある。主観申告は生体計測ではないので

一方で「熟達者との比較」という分かりやすい絵はなくなるため、指導教員の意向を確認したい。

**Q7（実験1）**: 現行の計画書は「1人90分×1回」であり、このままでは日間変動が原理的に観測できない。
Q5 の結果を受けて来訪回数を決め直す。参加者の負担と謝金が回数に比例する。

**Q8（新規性）**: `docs/novelty-analysis.md` の通り、手持ち13本はすべてバイオメカ・人間工学系であり
HCI側がまるごと空白。CHI / CHI PLAY / UIST / AHs の過去5年、身体スキル伝達系

## 5. この文書の値はすべて仮置きである

**重要: 本文書に書かれた数値・定義・設計はすべて仮の値であり、確定事項ではない。**

仮置きの目的は、決定を急ぐことではなく、**議論と実装を止めないこと**にある。空欄のままだと
センサも買えず、記録スクリプトも書けず、指導教員にも相談できない。仮でも値が入っていれば、
手を動かしながら「これは違う」と気づける。

具体的には次を意味する。

- **どの値も、根拠が出れば変えてよい。** 特に2章の力みの定義（筋ペア、区間、正規化）は、
  10月からの自己記録で実データを見れば変わる可能性が高い
- **3章の表の値は、ほぼ全て見積もりである。** Q5 の「週3回 × 8週間」や Q7 の「別日に3回」は、
  根拠のある数字ではなく、議論の出発点として置いた数
- **ただし1つだけ例外がある。** 2章の「**その日に測定したMVCで正規化する**」は仮置きではない。
  日をまたいで電極を貼り直す以上、これを外すと日間比較そのものが成立しない

### 確定させる期限

**力みの定義（2章の表）は、2026年12月末までに確定させる。**

理由は、実験1の主要指標として事前登録する必要があるためである。実験1のデータを見てから定義を
決めると、それは事前登録ではなくなり、多重比較の問題が戻ってくる。

それ以外の項目は、4章の表に従って随時見直す。
