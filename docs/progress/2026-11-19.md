## 今週の目標

  ゲームの結果（いつ的を倒したか・何発撃ったか）と時刻をそろえる

## やったこと

- マウスの動きとクリックを、時刻付きで記録するツールを作った
  - ゲームが前面にあっても、裏でマウスの生の移動量（横・縦）とボタンの押し・離しを受け取る
  - 時刻は筋電の記録と同じ時計で残す（次の「筋電とマウスを同時に記録」で合わせるため）
- 自分のマウス（4000 回/秒で送るもの）で 1 分記録し、細かさを確かめた
  - 約 125 回/秒しか届かなかったので、条件を変えて原因を切り分けた
- KovaaK's の結果の CSV の中身を確かめた（何が・どんな時刻の形で残るか）
- KovaaK's を 5 回（1 回約 60 秒、的が 6 つ出る壁を撃つシナリオ）遊びながら記録し、CSV と突き合わせた
- 記録が終わったら、KovaaK's の CSV を記録のフォルダへ自動でコピーするようにした
  - 生データを解析の前に手元へ集め、あとから書き換えないため。元のファイルは触らず、中身の指紋（ハッシュ）も残す
- マウスの移動量を照準の向き（角度）に直し、動きと撃った場所を図にした

## わかったこと

**M2-1「マウスとゲームの記録」への答え：ゲームの結果と、ミリ秒単位で時刻がそろった**

- 撃った数：5 回とも、CSV の発数と記録した左クリックの数が一致した（76・77・84・87・87 発）
- 倒した 370 体すべてで、倒した時刻は直前のクリックの 0.5〜4.8 ms 後（中央値 2.7 ms）。5 回ともほぼ同じ
- 外したクリックには、対応する倒した時刻がない。1 発ずつ当たり・外れを分けられる
- ゲームの結果の CSV には、倒した時刻・撃った数・スコアのほか、DPI・感度・視野角も残る。設定を別に記録しなくてよい
- スコアは「倒した数 × 精度 × 10」で決まる（5 回とも CSV のスコアと一致。例：65 × 0.855 × 10 = 555.9）

**スコアは 5 回で 556〜773 と動き、倒した数と精度に分けると落ちた理由が分かる**

- 倒した数は 65 → 82 と回ごとに増えた。精度は 86〜94 % の間で上下した
- 3 回目は倒した数が増えた（70 → 72）のに、精度が 91 → 86 % に落ちてスコアが下がった（636 → 617）
  - スコアが落ちる回を探すとき、「倒すのが遅かった」のか「外した」のかを分けて見られる
- 2〜5 回目は続けて遊び、スコアが上がり続けた。慣れやウォームアップの影響があるので、回の順番も一緒に見る必要がある

**記録の細かさ：ゲーム中は約 125 回/秒（8 ms ごと）まで。原因は Windows の仕組み**

- マウスは 4000 回/秒で送っているのに、記録には約 125 回/秒しか届かなかった
- 同じマウス・同じ PC で条件を変えると、記録する側が前面にないときだけ約 125 回/秒になり、前面にすると約 4300 回/秒になった
  - Windows は、前面にないアプリへのマウスの入力を、約 8 ms ごとにまとめて渡す
  - まとめるだけで、移動量の合計は変わらない（取りこぼしではない）
- ゲーム中はゲームが前面なので、記録は 8 ms ごとになる。前面を奪うとゲームの邪魔になるので、このまま進める
- できなかったこと：8 ms の細かさで足りるかは、まだ確かめていない。筋電と合わせたデータで、速い振りの形や筋電とのずれが見えるかを見る

**記録から、エイムの動きが読み取れる**

- 照準の速さを見ると、的ごとに「加速 → 減速 → 止まって撃つ」をくり返している
- 横・縦に分けて向き付きで見ると、どちらへ振ったか、行き過ぎて戻したかも分かる
- 移動量を足し合わせると、撃った場所が約 50 度 × 50 度の範囲（的が出る壁）に収まる。60 秒足しても範囲がずれていかない
- 角度の原点はシナリオ開始の向きにした。開始の向きを 0 にすると、撃った場所の範囲の中心は（−0.7, −0.9）度でほぼ 0
  - 開始すると画面が空間の中央に戻ることを、画面でも確かめた。毎回同じ正面を 0 にできる
- できなかったこと：動きの図は 1 回目だけで描いた。角度への直し方（1 カウント = 0.007 度）は、公開されている換算から計算した値で、実測はしていない
