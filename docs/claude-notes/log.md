  Raw Input ならマウスの生の移動量（dx, dy）が、ゲームが前面にあっても裏で取れる（RIDEV_INPUTSINK）
- **時刻は `time.perf_counter()`。** EMG の記録（`recording.py`）と同じ時計なので、M2-3 で合わせられる。開始時の値を `.json` に残す
- SendInput で合成した移動を 100 回送ると、記録は 34〜62 行になった。ただし移動量の合計は完全に一致したので、取りこぼしではなく、
  Windows が続けて届いた移動を 1 回にまとめただけ。本物のマウスでの報告レートは、本人が動かして確かめる
- **今週はマウス関係だけやる。家でやる**（本人）。センサが要らず、自分のマウスとエイム練習のソフトがある家のほうがやりやすいため

  - DPI・感度（`Sens Scale`・`Horiz Sens`）・FOV・解像度は CSV の末尾に残る。別に記録しなくてよい
  - 一時停止すると時間が飛ぶ（`Pause Count`・`Pause Duration`）。計測中は止めない。日付をまたぐ回は日付の扱いに注意

- **本物のマウスで `events` を 1 分回した**（家の PC、`data/raw/2026-11-17/mouse_test`）。60 秒・移動 5357 回・左クリック 65 回で、最後まで止まらず取れた
  - 移動の間隔は中央値 8.00 ms（約 125 Hz）、99% 点 14.96 ms。マウスは 4000 Hz なのに 125 Hz しか出なかった
- **125 Hz になる原因は Windows の間引き。** 前面にないアプリが Raw Input で受けると、通知は約 125 Hz にまとめられる（移動量の合計は保たれる）。
  切り分け（scratchpad の `phases.py`、裏で受けたまま 5 秒ずつ）：`events` と同じ作り 127 Hz、返し方を変えても 125 Hz、

  - 撃った数：最初に倒した的〜最後に倒した的の間の左クリック 76 回 = CSV の撃った数 76。一致
    （シナリオ開始の 0.16 秒前のクリック 1 回は数えない。開始のためのクリックと見られる）
  - 倒した時刻 − 直前の左クリック：65 体すべてで 1.0〜4.8 ms（中央値 2.8 ms）。壁時計どうしで ms 単位で合う
  - 比べたスクリプトは scratchpad の `align.py`（下の `kovaaks` コマンドに入れた）
- **実験の流れはツールに組み込み、当日はコマンドを打つだけにする**（本人と合意）。理由：Claude に毎回頼むとやり方が揺れ、PC を移ると経緯が消え、
  Claude が使えない日やほかの被験者のときに回せない。Claude は仕組みを作るのと結果を確かめるところを手伝う
- **生データは解析の前に手元に集め、あとから書き換えない**（本人）。そのため `python -m emgpipe kovaaks <events.csv>` を足した（`analysis/emgpipe/kovaaks.py`）。
  `events` のあとにも自動で走る（`--no-kovaaks` で止める）
  - 記録の間に始まったシナリオの CSV を、セッションの `kovaaks/` に日時を保ってコピー。元は触らない。同じ名前があれば上書きしない
  - コピー元・SHA-256・開始時刻などを `kovaaks/<記録名>_import.json` に残す（最初の取り込みのときだけ書く）。マウスの記録の `.csv`・`.json` は書き換えない
  - 見つからない・複数ある・一時停止がある・マウスの記録より後に終わった、はその場で警告
  - 取り込んだあと、撃った数と左クリックの数、倒した時刻と直前のクリックの差を出す。`kovaaks_test` で `align.py` と同じ結果（76 = 76、中央値 2.8 ms）
