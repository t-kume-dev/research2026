# 成果報告 2026-09-24

研究のストーリーと指標の方針を固めた。

---

## 1. ストーリー

1. **自分の良い状態を再現できない。** 上達したいが何を直せばいいか分からない。画面が返すのは
   命中率という結果だけで、身体をどう変えればいいかは教えてくれない
2. **だから量でしか解決できず、崩れても立て直せない**
3. **必要なのは「今日のあなたはここがずれている」と言ってくれるフィードバックである**
4. **だがフィードバックを作るには、返す中身が要る。** 何を返せば練習に使えるのかが分かっていない
5. **まず「返すべき指標」を同定する。** 次にそれを返して効くかを確かめる

> 練習に使えるフィードバックを作りたい。そのためにまず何を返せばいいかを見つけ、次にそれが効くか確かめる。

指標がなければフィードバックは作れないため、この順番は動かせない。

### 掲げ方は「上達」ではなく「実力を出し切れるようにする」

自己基準を採るため、支援の対象は到達点の向上ではなく「自分の良い状態の再現」になる。
ただし再現性の向上は上達の一部であり（巧緻運動の学習に伴い EMG の変動性が減少することが知られている）、
ベストを出せる頻度が上がることも上達である。

基準を固定テンプレートにせず、直近の良い試行から毎回作り直せば天井にはならない。

---

## 2. 指標の方針

**EMG を使い、基準は自己基準（自分の良い状態）とする。**

### なぜ自己基準か

**エイムは個人差が激しい世界であり、その中で「正解のロールモデル」を作ることは困難だと判断した。**
プロでも強く力んでいる人はいるし、腕の長さもマウスの持ち方も人によって違う。熟達者の中から
唯一の正しい型を定義できる見込みが立たない。基準を自分に置けば、この問題は丸ごと消える。

副次的な利点として、「どう直すか」の答えが自分の良かった試行の中に既に入っている。
「この前うまくいったときはこうだった」と言えるだけで実行可能な指示になり、他人の真似ではないため
個人差の問題も発生しない。

### 計測項目

**前腕EMG。** 毎日着けて練習する前提であり、重い装備は練習方法にならない。
心拍・脳波・視線などの生体情報は入れない。

---

## 3. EMG で具体的に何を取るかは、生データを見てから決める

当初は拮抗筋の共収縮指数を考えていたが、**Trigno の標準センサは前腕の個々の筋に対して大きすぎ、
ECR や FCR を単独で拾えない**。クロストークが避けられないため、筋ペアの共収縮はそのままでは成立しない。

代案の候補は次の3つ。どれが使えるかは実際の波形を見ないと判断できないため、
**指標の定義は生データを取ってから決める。**

| 候補 | 内容 | 利点 |
| --- | --- | --- |
| **静止区間の残余活動** | 出ているべきでない区間（待機中、クリック直前）に出ている筋活動を力みとする | どの筋かを特定する必要がないため、クロストークの影響を受けない |
| **区画レベルの共収縮** | 個々の筋ではなく、伸筋群と屈筋群の対立として見る | 大きいセンサが欠点でなくなる。区画間の分離が取れるかは要確認 |
| **振幅の変動性** | 大きさではなく、試行ごとのばらつきを見る | 熟達に伴って変動性が減ることが知られている |

## 4. 次にやること — 10月中に終わらせる

**Trigno から Python で生データを取り、MVC で正規化するところまで。**

既存の付属アプリでは必要な形でデータを扱いづらいため、自前で取得系を作る。

| # | やること | 完了基準 |
| --- | --- | --- |
| 1 | Trigno から Python で生データを取得する | 自分の腕で波形が出て、ファイルに落ちる |
| 2 | MVC 測定の手順を決めて実装する | 毎回同じ手順で MVC が取れる |
| 3 | MVC 正規化までのパイプラインを作る | 正規化済みの波形が出力される |
| 4 | 取れた波形を見て、指標の候補を絞る | 3章の候補のうちどれが使えるか判断できる |

**MVC 正規化は必須である。** 日をまたいで電極を貼り直す以上、その日の MVC で正規化しないと、
状態の変動なのか電極位置の違いなのか区別できない。
